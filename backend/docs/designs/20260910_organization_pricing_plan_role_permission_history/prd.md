# PRD：组织套餐角色权限历史恢复

> 日期：2026-09-10  
> 状态：已确认

## 1. 概述

当组织的套餐到期、暂停或切换时，普通角色在原套餐内配置的权限可能被移除。组织续费或重新购买曾使用过的套餐后，管理员不得不重新逐项配置权限。

本功能让系统记住组织在每个已离开套餐中的普通角色权限配置。在组织恢复或切回套餐时，系统按该套餐当前可提供的功能恢复此前配置；首次进入从未使用过的套餐时，系统不自动扩大权限。

## 2. 目标

- 组织恢复同一套餐后，恢复普通角色此前配置且仍可用的权限。
- 组织切回曾使用的套餐后，恢复该套餐下的历史角色配置。
- 套餐的当前功能范围始终是任何用户可访问功能的上限。
- 首次进入新套餐时不自动授予未配置权限。
- 套餐切换过程中，订阅状态和角色权限对用户呈现一致结果。

## 3. 本期范围

- 在套餐失效、暂停、切换或自动降级前保存普通角色在该套餐范围内的权限配置。
- 在续费、恢复、人工切换及自动到期降级时，按历史配置和当前套餐范围恢复权限。
- 限制一个组织同一时间只有一个有效套餐，并阻止组织购买类型不匹配的套餐。
- 角色或套餐删除后，不再保留其可恢复的历史权限。
- 保持现有规则：套餐新增功能不会自动授予普通角色。
- 所有用户的菜单与接口访问继续受当前有效套餐限制。

## 4. 非目标

- 不提供权限历史的查询、编辑、审计页面或对外接口。
- 不回填功能上线前的历史权限，也不猜测过去的授权配置。
- 不在管理员日常编辑角色权限时同步更新历史记录。
- 不建设独立授权系统、缓存、消息补偿或新的管理服务。
- 不改变公开功能的访问规则。

## 5. 用户与权限边界

- 平台管理员负责管理套餐、订阅和组织角色权限。
- 普通角色的历史配置可以保存和恢复；系统保留的管理员角色不参与该保存和裁剪流程。
- 组织所有者不是独立角色。所有者所使用的普通角色仍按普通角色规则处理；所有者与管理员可以访问当前套餐内可用功能，但都不得绕过套餐限制。
- 角色权限是组织内共享配置，不能因为某个成员是组织所有者而跳过处理。

## 6. 用户故事

### US-001：离开套餐时保留角色配置

**描述：** 作为平台管理员，我希望系统在组织离开套餐前保留普通角色的可用权限，以便以后恢复。

**验收标准：**

- [ ] 套餐失效、暂停、切换或自动降级前，系统保存每个普通角色在来源套餐范围内的权限和数据范围。
- [ ] 保留的管理员角色不因该流程被修改。
- [ ] 保存失败时，组织不进入半完成的套餐切换状态。

### US-002：恢复同一套餐

**描述：** 作为组织管理员，我希望在续费或恢复套餐后找回此前已配置的角色权限，避免重复配置。

**验收标准：**

- [ ] 原套餐重新生效后，普通角色恢复此前保存且仍属于该套餐当前范围的权限。
- [ ] 当前套餐已经移除的功能不得因历史记录恢复。
- [ ] 恢复后，普通角色不保留套餐范围外的非公开权限。
- [ ] 同一套餐仅延长有效期时，不覆盖管理员在套餐有效期间做出的日常权限编辑。

### US-003：切回已使用套餐

**描述：** 作为组织管理员，我希望切回过去使用过的套餐时恢复当时的角色配置，同时遵守套餐最新内容。

**验收标准：**

- [ ] 切换前保存来源套餐中的普通角色配置。
- [ ] 目标套餐存在历史配置时，系统恢复其中仍在目标套餐当前范围内的权限。
- [ ] 目标套餐后来新增、但历史上未配置的功能不会被自动授予。
- [ ] 历史中存在、但目标套餐后来移除的功能不会被恢复。

### US-004：首次进入新套餐

**描述：** 作为平台管理员，我希望组织首次进入新套餐时权限保持最小化，避免意外扩大访问范围。

**验收标准：**

- [ ] 目标套餐没有历史配置时，普通角色只保留其当前已有且仍属于新套餐范围的权限。
- [ ] 系统不因套餐包含更多功能而自动授予普通角色权限。
- [ ] 组织以后离开该套餐时，系统才为该套餐保存首次历史配置。

### US-005：保持订阅与权限边界一致

**描述：** 作为平台管理员，我希望套餐和权限规则始终一致，避免组织获得不应访问的功能。

**验收标准：**

- [ ] 系统拒绝组织类型与套餐类型不匹配的订阅。
- [ ] 同一组织同一时间最多一个有效套餐。
- [ ] 角色或套餐删除后，其历史权限不再被恢复。
- [ ] 所有用户（包括组织所有者和管理员）均不能访问当前套餐范围外的功能。

## 7. 功能需求

- FR-1：系统必须在普通角色离开有效套餐前保存其在来源套餐范围内的权限配置。
- FR-2：系统必须在同一套餐恢复有效时恢复此前保存且仍属于该套餐当前范围的权限。
- FR-3：系统必须在切回有历史记录的套餐时恢复符合当前套餐范围的历史权限。
- FR-4：系统必须在首次进入没有历史记录的套餐时仅保留当前权限与目标套餐范围的重叠部分。
- FR-5：系统不得因套餐新增功能自动授予普通角色权限。
- FR-6：系统必须始终以当前套餐的功能范围限制权限恢复结果和实际访问权限。
- FR-7：系统必须在订阅到期、暂停、续费、状态切换、人工切换及自动降级时应用相应的保存、恢复或裁剪规则。
- FR-8：系统必须在删除角色或套餐后移除关联的可恢复权限历史。
- FR-9：系统必须拒绝组织类型与套餐类型不匹配的订阅。
- FR-10：系统必须保证每个组织同一时刻最多一个有效套餐订阅。
- FR-11：套餐、订阅或权限变更失败时，系统不得向用户呈现部分完成的授权结果。
- FR-12：组织所有者和管理员的访问权限必须继续受当前有效套餐限制。

## 8. 成功指标

- 同套餐恢复后，普通角色此前配置且仍可用的权限全部恢复。
- 切回旧套餐时，不恢复已移除功能，也不自动授予未保存的新功能。
- 任一失败场景不产生部分完成的订阅或权限变更。
- 订阅切换、自动降级、暂停恢复、角色删除和套餐删除的回归验证全部通过。

## 9. 已确认产品决策

| 决策 | 结论 |
| --- | --- |
| 历史范围 | 按组织、套餐和普通角色保存其权限配置。 |
| 恢复上限 | 以恢复时套餐当前功能范围为上限。 |
| 新套餐 | 无历史时只最小化保留现有权限，不自动授予。 |
| 历史时机 | 仅在实际离开套餐时保存，不随日常权限编辑更新。 |
| 上线前数据 | 不回填历史；缺失历史时按首次进入新套餐处理。 |
| 保留角色与所有者 | 管理员角色不参与历史处理；所有者所使用的普通角色仍参与，且两者访问都受套餐范围限制。 |
