**创建日期**: 2026-01-23

## 用户场景与测试 *(必填)*

### 用户故事 1 - 管理基础模板 (优先级: P1)

管理员用户需要创建和管理基础邮件和合同模板，这些模板可以分发给组织。这些模板作为组织定制化的基础。

**为何设置此优先级**: 这是核心功能 - 没有基础模板，整个模板系统就没有基础。管理员必须能够创建、查看、更新和启用/禁用基础模板。

**独立测试**: 可以通过管理员界面创建基础模板来完全测试，验证它出现在模板列表中，更新其内容，并禁用它。通过建立模板库提供即时价值。

**验收场景**:

1. **假设**管理员用户已登录，**当**他们创建具有名称、类型（借款方/贷款方）、类别（邮件/合同）、标签、内容和变量架构的新基础模板时，**那么**该模板将被保存并显示在基础模板列表中，状态为启用
2. **假设**存在多个基础模板，**当**管理员查看模板列表时，**那么**他们可以看到所有模板并支持分页，可以按类型、类别、标签和状态进行筛选
3. **假设**存在一个基础模板，**当**管理员更新其内容或变量架构时，**那么**更改将被持久化，updated_at 时间戳将被刷新
4. **假设**一个启用的基础模板有关联的组织模板，**当**管理员禁用该基础模板时，**那么**所有派生的组织模板也将被禁用
5. **假设**一个禁用的基础模板有关联的组织模板，**当**管理员重新启用该基础模板时，**那么**所有派生的组织模板也将被重新启用

---

### 用户故事 2 - 级联删除行为 (优先级: P2)

管理员用户需要了解并控制删除已分发到组织的基础模板时会发生什么。

**为何设置此优先级**: 数据完整性至关重要 - 管理员必须了解删除模板的影响。这比基本 CRUD 优先级低，但比组织特定管理优先级高，因为它可以防止意外数据丢失。

**独立测试**: 可以通过创建基础模板、将其分发到组织，然后尝试删除并验证所有相关的组织模板都被删除来测试。

**验收场景**:

1. **假设**一个基础模板有多个派生的组织模板，**当**管理员删除该基础模板时，**那么**所有组织模板也将被删除且无法恢复
2. **假设**一个基础模板没有组织模板，**当**管理员删除它时，**那么**只有基础模板被删除
3. **假设**管理员尝试删除基础模板，**当**系统确认删除时，**那么**显示警告指示有多少组织模板将受到影响

---

### 用户故事 3 - 模板变量架构管理 (优先级: P3)

管理员用户需要为模板定义复杂的变量结构，包括嵌套对象和数组，以支持动态内容生成。

**为何设置此优先级**: 虽然对于高级用例很重要，但基本模板可以使用简单的变量架构。这支持复杂的模板定制，但对初始发布不是阻塞因素。

**独立测试**: 可以通过创建具有复杂变量架构的模板来测试，包括具有嵌套属性的对象类型和具有多个项目的数组类型。

**验收场景**:

1. **假设**管理员正在创建模板，**当**他们定义包含多个变量（包括字符串、数字、布尔、数组、对象类型）的变量组时，**那么**该架构被存储并可以被检索用于验证
2. **假设**一个对象类型的变量，**当**管理员定义嵌套属性时，**那么**完整的嵌套结构被保留并可检索
3. **假设**一个数组类型的变量，**当**管理员定义项目架构时，**那么**数组结构被维护用于模板处理

---

### 边界情况

- 当管理员尝试创建在同一类型和类别中具有重复名称的模板时会发生什么？
- 系统如何处理 variable_group_schema 字段中的无效 JSON？
- 当组织模板正在使用而其基础模板被删除时会发生什么？
- 系统如何处理具有非常大内容（>10MB）的模板？
- 当管理员尝试禁用特定类型和类别的所有模板时会发生什么？
- 系统如何处理对同一模板的并发更新？

## 需求 *(必填)*

### 功能需求

- **FR-001**: 系统必须允许管理员用户创建具有以下属性的基础模板：名称、类型（借款方/贷款方）、类别（邮件/合同）、标签、内容、variable_group_schema、状态和描述
- **FR-002**: 系统必须验证模板类型为"借款方"或"贷款方"
- **FR-003**: 系统必须验证模板类别为"邮件"或"合同"
- **FR-004**: 系统必须验证模板状态为"启用"或"禁用"
- **FR-005**: 系统必须将 variable_group_schema 存储为有效的 JSON 结构
- **FR-006**: 系统必须允许管理员用户查看支持分页的基础模板
- **FR-007**: 系统必须允许按类型、类别、标签和状态筛选模板
- **FR-008**: 系统必须允许管理员用户更新基础模板属性
- **FR-009**: 系统必须自动跟踪 created_at 和 updated_at 时间戳
- **FR-010**: 系统必须使用 is_del 标志实现软删除
- **FR-011**: 系统必须级联状态更改：当基础模板被禁用时，所有派生的组织模板也被禁用
- **FR-012**: 系统必须级联状态更改：当基础模板被重新启用时，所有派生的组织模板也被重新启用
- **FR-013**: 系统必须级联删除：当基础模板被删除时，所有派生的组织模板也被删除
- **FR-014**: 系统必须提供按模板名称和标签的搜索功能
- **FR-015**: 系统必须在类型和类别组合中强制执行模板类型与标签组合的唯一性约束
- **FR-016**: 编辑基础模板时，不可改变标签。标签是基础模板的唯一标识符，用于组织和检索模板。

### 关键实体

- **基础模板**: 作为组织模板基础的主模板。包含名称、类型（借款方/贷款方）、类别（邮件/合同）、标签、内容、变量架构（JSONB）、状态（启用/禁用）、描述和时间戳。基础模板可以分发给多个组织。

- **组织模板**: 从基础模板派生的模板，分配给特定组织。继承基础模板结构但可以自定义。包含所有基础模板字段加上 organization_id 外键。当父基础模板更改状态或被删除时，组织模板相应级联。

- **模板变量**: 变量组中的单个变量定义。具有标签、类型（字符串/数字/布尔/数组/对象）、键、is_editable 标志、来源（固定/动态）、fixed_value、example_value，以及可选的 properties（用于对象类型）或 items（用于数组类型）。

- **变量组**: 相关的模板变量集合。具有名称并包含多个变量。组有助于将复杂的模板架构组织成逻辑部分。

## 成功标准 *(必填)*

### 可衡量的结果

- **SC-001**: 管理员用户可以在 60 秒内创建包含所有必填字段的新基础模板
- **SC-002**: 模板列表页面在 2 秒内加载并显示最多 100 个模板
- **SC-003**: 对于包含多达 10,000 个模板的数据库，搜索和筛选操作在 1 秒内返回结果
- **SC-004**: 状态更改操作（启用/禁用）在 3 秒内完成，包括对所有组织模板的级联
- **SC-005**: 100% 的基础模板状态更改正确级联到所有派生的组织模板
- **SC-006**: 100% 的基础模板删除正确删除所有派生的组织模板
- **SC-007**: 变量架构验证在保存前拒绝 100% 的无效 JSON 结构
- **SC-008**: 管理员用户 95% 的时间在第一次尝试时成功创建模板

## 假设

1. 管理员用户已经具有适当的身份验证和授权
2. 系统使用 PostgreSQL 并支持 JSONB 用于变量架构存储
3. 模板内容是纯文本或 HTML（此阶段不包含二进制文件存储）
4. 组织模板通过单独的分发过程创建，本规格说明未涵盖
5. 变量架构验证在数据库持久化之前在 API 层进行
6. 软删除（is_del 标志）优先于硬删除以用于数据恢复
7. 模板名称区分大小写用于唯一性验证
8. 级联操作使用数据库触发器或应用层逻辑
9. 分页默认每页 20 项，页面大小可配置
10. 管理员界面存在并为这些操作提供 UI（本规格仅涵盖后端功能）
